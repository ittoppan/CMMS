# คู่มือการใช้งาน CMMS-TPT (เน้นมือถือ + LINE)

> แนะนำให้ใช้ผ่าน LINE / มือถือเป็นหลัก ระบบทั้งหมดเข้าถึงได้ผ่าน
> `https://ommatophorous-robert-fortifyingly.ngrok-free.app/`

---

## 1. การเข้าสู่ระบบ

| ช่องทาง | วิธี |
|---|---|
| **LINE (แนะนำ)** | กดปุ่ม Rich Menu / ลิงก์จากแชท แล้วกด "ล็อกอินด้วย LINE" — ครั้งแรกต้อง **ผูกบัญชี** ก่อน (ข้อ 2) ครั้งต่อไปเข้าได้ทันที |
| **เว็บเบราว์เซอร์** | เปิด URL ระบบ → กรอก Username/Password (เช่น `E01117` / `password`) หรือกด "เข้าสู่ระบบด้วย LINE" |
| **แอป (PWA)** | บนมือถือเปิดหน้า `/` → เมนูเบราว์เซอร์ → "Add to Home screen" — ใช้เหมือนแอป |

**ข้อควรรู้**
- ระบบจำได้ว่าใครเป็นใครผ่าน LINE ID ที่ผูก → งานที่แจ้งจะใส่ชื่อผู้แจ้งให้อัตโนมัติ
- ปุ่ม "บัญชีทดสอบ" ในหน้า Login มีไว้ทดสอบระบบ (ปิดได้ที่การตั้งค่า)

## 2. ลงทะเบียนผูกบัญชี LINE (Line Binding)

จุดประสงค์: เชื่อม LINE ID ↔ เลขพนักงานในระบบ ครั้งเดียวจบ แล้วรับการแจ้งเตือนทาง LINE

1. เปิดหน้า **`/register`** (จาก Rich Menu กด "ลงทะเบียน")
2. กด **"ล็อกอินด้วย LINE"** → ระบบพากลับมามากับ LINE ID ของคุณ
3. **กรอกเลขพนักงาน** (เช่น `E01117`) → กด **ผูกบัญชี**
4. เห็นหน้าจอ "ผูกบัญชีสำเร็จ!" + ได้ข้อความยืนยันในแชท LINE

> ถ้าผูกไว้แล้ว หน้า `/register` จะบอก "บัญชีนี้ผูกกับ X แล้ว" และพาไปแจ้งซ่อมได้เลย
> เปิดใน LINE ตรงๆ (ผ่าน LIFF) ระบบจะเติม LINE ID ให้เองอัตโนมัติ — ไม่ต้องกรอก

## 3. เมนูหลักบนมือถือ (Rich Menu / หน้าแรก)

ลิงก์ที่ใช้บ่อย (ตั้งเป็นปุ่มใน Rich Menu ได้):

| ปุ่ม | URL | ใช้ทำอะไร |
|---|---|---|
| หน้าแรก / เมนู | `/` | เมนูตามสิทธิ์ผู้ใช้ (บทบาท admin / หัวหน้า / ช่าง / ผู้ใช้งาน) |
| ลงทะเบียนผูก LINE | `/register` | ผูกบัญชีครั้งแรก / เปลี่ยนการผูก |
| สแกน QR เครื่อง | `/scan` | ชี้เครื่องจักรดูข้อมูล / ไปแจ้งซ่อม / ทำ PM (กรอกรหัสเครื่องเองได้) |
| แจ้งซ่อม | `/repair/request` | สร้างใบแจ้งซ่อม F-EN-03 |
| ศูนย์อนุมัติ | `/approval` | รายการขออนุมัติที่ค้าง (อะไหล่ / เอกสาร / งาน) |

## 4. แจ้งซ่อม (เครื่องจักรพัง/ผิดปกติ)

**วิธีที่ 1 — จาก QR ที่ตัวเครื่อง (ไวที่สุด)**
1. เปิดกล้อง LINE สแกน QR สติกเกอร์ที่เครื่อง → ได้ URL `/scan?asset_code=EN-xxxxx`
2. เห็นข้อมูลเครื่อง + ปุ่ม **"แจ้งซ่อม"** หรือ **"ทำ PM"**
3. เลือก **แจ้งซ่อม** → กรอกอาการ/ความเร่งด่วน/อัพรูปถ่ายก่อนซ่อม → ส่ง

**วิธีที่ 2 — กดจากเมนู**
- กด "แจ้งซ่อม" → เลือกเครื่อง ระบุอาการ เหมือนข้างบน

**หลังส่ง** — ระบบแจ้งเตือนอัตโนมัติ:
- LINE ห้องกลุ่มช่าง / หัวหน้าซ่อม (พร้อมรูป + ปุ่มดูใบซ่อม)
- LINE Push ถึงช่างที่ได้รับมอบหมาย (เมื่อถูก assign)
- Email แจ้งผู้ที่เกี่ยวข้อง
- งานขึ้นทันทีที่หน้า "งานของฉัน / Kanban ใบซ่อม"

## 5. งานของช่าง (รับงาน / ทำงาน / ปิดงาน)

1. เมนู → **งานของฉัน** `/repair/my_tasks` → เห็นงานที่ถูกมอบหมาย
2. กดงาน → ดูรายละเอียด + อัพรูประหว่างซ่อม
3. กด **รับงาน** (เริ่มนับเวลา) → **ปิดงาน** → บันทึกสาเหตุ/อะไหล่ที่ใช้/เวลาดาวน์ไทม์
4. ปิดงานแล้วระบบส่ง LINE ยืนยัน "ซ่อมเสร็จ" พร้อมปุ่มประเมินผล

> งานด่วน (Breakdown) แจ้งผ่าน LINE สีแดง + เด้งแจ้งเตือนให้ช่างทันที

## 6. งาน PM/AM (บำรุงรักษาเชิงป้องกัน)

> **กฎสำคัญ: ทำ PM ได้เฉพาะวันครบกำหนด (due date) ของแผนนั้นพอดี** — ถ้ายังไม่ถึงวัน หรือเลยกำหนดแล้ว รายการจะไม่โผล่ให้ทำ (หน้าเช็คชีตขึ้นข้อความแจ้งวันกำหนด) และระบบกันที่ฝั่งเซิร์ฟเวอร์ด้วย (บังคับแม้ส่งงานค้าง offline)

1. เมนู → **แผน PM/AM** → เห็นรายการตามกำหนด (เมนูปฏิทิน `/pm_am/calendar`)
2. โปรดรอจนถึงวัน due_date → หน้าเช็คชีต `/pm_am/checksheet` จะแสดงเฉพาะแผนที่ครบกำหนดวันนี้เท่านั้น (เข้าจาก QR เครื่อง → ระบบเลือกแผนให้อัตโนมัติ)
3. ตรวจตามรายการ → ลงนาม 2 ฝ่าย (ผู้ตรวจ + ผู้ควบคุมเครื่อง) → **บันทึกผล** → ระบบสร้างรอบถัดไปตามรอบความถี่อัตโนมัติ (รายวัน/สัปดาห์/เดือน/ไตรมาส/ปี)
4. ถ้าช่างแน่ใจว่าต้องเลื่อนกำหนด → กด **ขอเลื่อน (deferral)** → ส่ง Line ให้หัวหน้า/แอดมินอนุมัติ

## 7. เบิกอะไหล่ + **การอนุมัติ** (หัวใจข้อนี้)

### ช่าง/ผู้ขอเบิก
1. ในใบซ่อม (หรือเมนูอะไหล่) กด **ขอเบิกอะไหล่** → เลือกรายการ + จำนวน
2. ระบบเปลี่ยนสถานะเป็น **"รออนุมัติ"** (`pending`) แล้ว **แจ้งเตือนไปที่ผู้อนุมัติ (หัวหน้า/แอดมิน) ทั้ง 2 ช่องทางพร้อมกัน**:
   - **LINE**: การ์ด "🧰 ขอเบิกอะไหล่ #xxx รออนุมัติ" พร้อม **ปุ่ม "✅ อนุมัติการเบิก" / "❌ ไม่อนุมัติ"** (กดอนุมัติในแชทได้เลย ไม่ต้องเปิดเว็บ — หรือปุ่มเปิดหน้าใบซ่อมก็ได้)
   - **Email**: อีเมลถึงผู้อนุมัติ พร้อม **ปุ่ม "อนุมัติ" / "ไม่อนุมัติ"** (ลิงก์ไปหน้าอนุมัติ 1-Click)

### ผู้อนุมัติ (หัวหน้า/แอดมิน)
- **ทาง LINE**: แตะปุ่มบนการ์ดแจ้งเตือน → อนุมัติ/ไม่ทันที (ระบบบันทึกชื่อผู้พิจารณา เวลา) → ช่างผู้ขอกดรับการแจ้งเตือนผลทันที
- **ทาง Email**: กดปุ่มในอีเมล → เปิดหน้าเว็บอนุมัติ (ลิงก์เฉพาะครั้งเดียว ไม่ต้องล็อกอินซ้ำ) → กดยืนยัน
- **ศูนย์อนุมัติรวม**: เมนู **ศูนย์อนุมัติเอกสาร** `/approval` (หรือ `/pages/approval/center.php`) → เห็นคำขอค้างทั้งหมด → อนุมัติ/ไม่อนุมัติเป็นชุด หรือกดลิงก์ให้

### หลังอนุมัติ
- อะไหล่ถูกตัดจากสต็อก / ผูกกับใบซ่อมที่เบิก → ช่างเห็นสถานะในใบงาน → ตัดเบิก / Sage ส่ง PO (ถ้าใช้)

# คำแนะนำ (Recommendations)

**แนะนำให้ทำต่อเร็วๆ นี้**
1. **สร้าง LIFF App ของหน้า `/register`** ใน LINE Developers console (endpoint = `https://ommatophorous-robert-fortifyingly.ngrok-free.app/register`) แล้ววาง LIFF ID ที่ *Settings → การแจ้งเตือน → "LIFF App ID (หน้า /register)"* — ลดขั้นตอนล็อกอิน 2 คลิก สำหรับการผูกบัญชี
2. **อัปเดต `TELEGRAM_BOT_TOKEN`** ใน `.env` (token เดิมถูก revoke แล้ว API ตอบ 404) — ระบบแจ้งแอดมินทาง Telegram (เช่น "มีผู้ผูกบัญชีใหม่", การแก้ไขตั้งค่า) จะกลับมาทำงาน
3. **ตั้ง Rich Menu จริง**: รูป 2500×843 → 3 ปุ่ม: "แจ้งซ่อม" `…/scan`, "ลงทะเบียนผูก LINE" `…/register`, "หน้าแรก" `…/` ; ตรวจ Home URL ชี้ไป ngrok URL
4. **ทดสอบ e2e จริงบน LINE**: ล็อกอิน → /register → ผูก → แจ้งซ่อม → เบิกอะไหล่ → ผู้อนุมัติกดปุ่มใน LINE → เช็คว่าช่างได้ LINE แจ้งผล

**แนะนำฟีเจอร์ที่ควรเพิ่ม (ถ้าอยากได้)**
- **การ์ด LINE แบบรวมงานด่วนของวัน** (daily digest) ดีกว่า weekly
- **ปุ่ม Deep-link ในทุกการ์ด /scan·/repair ให้ไปหน้าเฉพาะของงาน** เช่น `/repair/view?id=xx` (บางจุดยังลิงก์ไปหน้าแรก)
- **การแจ้งเตือนปุ่ม "ลองดูหน้าเว็บที่สวยงาม"** — เปิด `?v=2` ถ้าเห็นหน้าเก่า (ล้าง cache 1 ปีเดิม)
- **LINE Simple Rich Menu (2 ปุ่ม)** สำหรับคนอ่านออกง่าย: "แจ้งซ่อม" + "งานของฉัน"
- **การอนุมัติแบบหลายขั้น (multi-step approval)** ถ้าธุรกิจโตแล้วอยากได้ flow chain
- **รายงาน PDF/Excel ส่งเข้า LINE อัตโนมัติ** รายสัปดาห์ — ตรงกับคอนเซ็ปต์ชากงานกระดาษ F-EN-xx

**สถาปัตยกรรม/ความปลอดภัยที่ทำไว้แล้ว**
- Tunnel = ngrok static (webhook + login callback + notification URL ตั้งอัตโนมัติ)
- ทุก POST/PUT/DELETE ผ่าน CSRF check; ไม่มี secret ใน git (อ่านจาก `.env`)
- LINE Login ใช้ channel แยกจาก Bot channel; webhook ดริฟท์เช็คอัตโนมัติ
