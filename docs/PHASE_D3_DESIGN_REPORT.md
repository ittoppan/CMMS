# PHASE D3 — Design Report (Work Order Control)

> Phase 6 · 2026-11-23 · ขอบเขต: `/supervisor`, `/supervisor/queue`, `/repair/view`
> เอกสารนี้สรุป "ทำไมหน้าตาจึงเป็นแบบนี้" ของงาน D3.2–D3.6 โดยอ้างอิงโค้ดที่ commit แล้ว

## 1. เป้าหมายการออกแบบ

1. หัวหน้างานเปิดมาแล้วเห็น "สิ่งที่ต้องทำวันนี้" ก่อนรายละเอียด (KPI → งานที่ต้องติดตาม → คิว → แนวโน้ม)
2. ทุกตัวเลขที่เกี่ยวกับเวลา (เกินกำหนด/เหลือกี่วัน) ต้องอ่านออกด้วยหางตา ไม่ต้องตีความ
3. หน้าจอเดียวใช้ได้ทั้ง 1440 / 768 / 390 โดยไม่ต้องมีเลย์เอาต์คนละชุด
4. ไม่แตะ logic/API/permission/route — เปลี่ยนเฉพาะ markup, สีจาก token, และลำดับข้อมูลบนจอ

## 3. การตัดสินใจสำคัญ

### 3.1 Aging ต้องเป็น "สถานะ" ไม่ใช่แค่ตัวเลข

`/repair/view` คำนวณ `aging` จาก `sla_due_at` → `estimated_completion_date` (สูตรเดียวกับ `src/helpers/kpi.php`) แล้วแปลเป็น 6 ป้าย:

| เงื่อนไข | ป้าย | สี |
|---|---|---|
| due ผ่านแล้ว และงานยังไม่จบ | เกินกำหนด N วัน | danger |
| เหลือ ≤ 1 วัน | ครบกำหนดวันนี้/พรุ่งนี้ | warning |
| เหลือ 2–3 วัน | ใกล้ครบกำหนด | warning (อ่อน) |
| เหลือ > 3 วัน | เหลือ N วัน | neutral/info |
| ไม่มี due และค้าง > 7 วัน (งานเปิด) | ค้างมา N วัน | warning |
| งานจบแล้ว (`closed/cancelled/rejected/verified/done/skipped/completed/resolved`) | ปิดภายใน N วัน | success/neutral |

- **ความต่างที่ตั้งใจจาก KPI**: ฝั่งจอเพิ่ม `completed`/`resolved` เข้าชุด "งานจบ" เพื่อไม่ให้ใบงานที่ปิดแล้วขึ้นคำว่า "เกินกำหนด" (คิว KPI กรองงานปิดออกอยู่แล้ว ผล KPI จึงไม่เปลี่ยน)
- ไม่มี due และยังไม่เกิน 7 วัน → ไม่แสดงป้าย (ไม่สร้างความ alarms ปลอม)

### 3.2 ตัวเลขที่ต้องตัดสินใจ = วางใกล้ปุ่มที่ใช้ตัดสินใจ

- คิว: ชื่อ + เครื่องจักร + ความสำคัญ + สถานะ + ผู้รับผิดชอบ + กำหนดเสร็จ อยู่ในแถวเดียว (desktop) หรือการ์ด 2 คอลัมน์ (tablet/mobile)
- รายละเอียด: "กำหนดเสร็จ (SLA)" มีจุดสี + ป้าย aging อยู่ในบล็อกสรุปบนสุด ไม่ต้องเลื่อนหา
- `primaryAction` ของหน้า detail = "พิมพ์เอกสารปิดซ่อม" (งานที่หัวหน้างานทำบ่อยที่สุดหลังตรวจรับ) ปุ่มอื่นเป็น secondary

### 3.3 ตาราง → การ์ด ที่ breakpoint เดียวกัน

- `/supervisor/queue`: ตารางที่ `lg` ขึ้นไป, การ์ดที่ต่ำกว่า (เดิมเริ่มการ์ดที่ `md` แต่ตารางยังกว้าง 1,110px ที่ 768 จึงเลื่อนแนวนอนในกรอบ)
- `/repair/view`: ตารางอะไหล่ที่ขอ และตารางใบเบิกอะไหล่ ใช้ `md` เป็นจุดสลับ เพราะตารางแคบกว่า (6 คอลัมน์สั้น)
- ทุกกรณี: overflow แนวนอนอนุญาตเฉพาะ "ในกรอบตาราง" ไม่ใช่ระดับหน้า

### 3.4 สีจาก token ไม่ใช่ hex ในหน้า

- งาน D3.6 ปรับ `--color-text-muted` / `--cmms-text-muted` เป็น `#5B6B80` (จาก #64748B) เพราะ 4.43:1 ไม่ผ่าน AA บนพื้นหน้า — แก้ที่ token เดียว ทุกหน้าได้ประโยชน์
- เอกสารปิดงาน (`WorkOrderClosureDocument`) ยังเป็น inline style แบบเดิม แต่ปรับเฉพาะค่าสีของสถานะให้ผ่าน AA (`#15803D`, `#B91C1C`, `#475569`) โดยไม่รื้อโครงสร้าง

## 4. สิ่งที่จงใจไม่ทำ

- ไม่เปลี่ยนสูตร KPI, ไม่เพิ่ม KPI ใหม่, ไม่เพิ่มคอลัมน์ที่ต้องมี API ใหม่
- ไม่เพิ่มฟิลเตอร์แผนก/ช่วงวันที่ในคิว เพราะ `supervisor.php` ยังไม่รองรับ (ต้องอนุมัติแก้ API)
- ไม่แก้ `statusLabel`/`statusLabels` ที่กลายเป็น dead code — เก็บกวาดใน Phase 2 พร้อมกันทั้งโปรเจกต์
- ไม่แตะ dark mode (ยังไม่มีค่าทับเฉพาะของ token ชุดนี้) — บันทึกเป็น known issue
